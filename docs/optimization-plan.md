# Ptrade Order Tool 优化方案

## 背景

当前工具已经覆盖核心工作流：导入 PTrade 盘后 JSON、编辑订单、逐条确认、校验并导出给 PTrade 策略脚本读取的订单 JSON。进一步优化的目标不是扩展交易逻辑，而是减少误操作、降低每日复盘成本，并让界面状态更容易判断。

## 优先级原则

1. 先做能降低交易计划错误概率的改动。
2. 先做不改变导出 JSON 契约的改动。
3. 先做可自动化测试覆盖的改动。
4. 视觉优化优先服务信息密度和状态可读性。

## 第一阶段：交互可靠性

- 订单编辑后必须自动回到未确认状态，导出前强制重新确认。
- 导出前检查应区分“阻断项”和“提醒项”，并展示可执行的摘要。
- 导出成功后展示完整文件路径，便于用户核对和拷贝到 PTrade 环境。
- 手动添加股票出现多个候选时，弹出候选选择，而不是只显示错误。
- 历史日期继续保持只读，但文案明确“只读，可重新导出”。

## 第二阶段：日常效率

- 增加顶部工作流状态：已导入、待确认、检查通过、已导出。
- 增加导出目录打开按钮。
- 股票搜索支持键盘回车添加。
- 候选股票列表展示代码、名称、市场，减少同名误选。
- 对未确认订单提供快速定位入口。

## 第三阶段：工程结构

- 将订单编辑状态从重复 widget 中抽到单一 UI 状态模型，减少多标签页同步代码。
- 给桌面导出 JSON 与 PTrade runtime 读取逻辑增加契约测试。
- 增加应用日志文件，记录导入、继承、确认、导出和 Tushare 更新结果。
- 为 Tushare 更新任务建立统一状态机，支持失败重试和明确的缺 Token 状态。
- 打包配置排除开发、科学计算、交互式环境等无关模块，控制 PyInstaller 产物体积。

## 第四阶段：视觉与信息层级

- 将顶部账户区、操作区、股票卡片区做更明确的层级分隔。
- 未确认、已确认、继承待确认使用更稳定的视觉状态。
- 买入、止盈、止损保持颜色区分，同时用图标或短标签降低文字负担。
- 空状态、错误状态、导出成功状态统一样式。
- 压缩卡片内重复按钮尺寸，提高列表扫描效率。

## 本次执行范围

本次执行第一阶段中风险低、收益明确的项目：

- 多候选股票弹窗选择。
- 导出前检查摘要。
- 导出成功路径反馈。
- 历史日期状态文案明确化。
- 补充对应自动化测试。

## 继续执行范围

本轮继续落地以下项目：

- 修复 `pypinyin` 第三方弃用警告，并延迟加载拼音库以降低启动导入成本。
- 搜索框支持回车添加股票。
- 增加打开导出目录按钮。
- 增加桌面导出字段与 PTrade runtime 读取字段的契约测试。
- 调整 PyInstaller spec，移除 `pypinyin` 全量 hidden import，并排除无关大模块。

## 本轮继续执行范围

- 增加轻量轮转日志 `app.log`，记录启动导入、订单修改、确认、删除、撤销、手动加股和导出。
- 增加“定位未确认”按钮，直接跳到第一条待确认订单所在股票卡片。
- 保持实现使用标准库和现有 PySide6 能力，不增加新的运行依赖。

## 结构性优化执行范围

- 将“全部 / 开仓 / 持仓”从三套重复卡片改为一套股票卡片加标签过滤。
- 删除重复 widget 带来的跨标签页订单状态同步路径，只在订单类型变化时重绘当前单一卡片集。
- 降低 UI 对象数量，减少编辑状态分裂风险，后续维护集中在一套 `StockCard` / `OrderRow` 上。

## 产品层优化执行范围

- 增加“导出检查”按钮，在正式导出前集中展示待确认、阻断项和提醒项。
- 检查面板保留“定位未确认”入口，用户可以从问题列表直接回到需要处理的订单。
- 导出按钮继续执行强校验，检查面板只作为提前确认和排查工具，不改变导出 JSON 契约。

## 视觉细化执行范围

- 重写全局样式表，统一专业工作台色板、按钮层级、卡片边界和状态 badge。
- 将订单行颜色从内联样式迁移为属性驱动的全局样式，降低控件代码中的视觉逻辑。
- 缩短订单分组文案和新增按钮文案，降低重复文字噪音。
- 将导出检查弹窗从单列表改为“待确认 / 阻断项 / 提醒项”三个分组区块。
- 保持无新增图标库和无新增运行依赖，避免增加打包体积。
